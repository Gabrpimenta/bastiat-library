# AI-assisted implementation record — 21 September 2026

Objective: implement the approved learning journey with verifiable native media, offline persistence, CMS publishing and cross-client progress.

Tools actually used: Codex for implementation and review; local Node/pnpm, PostgreSQL, Xcode and Gradle for execution; Vitest, Playwright and Maestro for checks; FFmpeg and Kokoro for original demonstration media. No claim is made that a separate human or independent agent reviewed the code. Maintainer review remains a release requirement.

Human decisions supplied to the implementation: project scope, editorial direction, initial single-course content set and the request for professional AI contribution rules. The record omits private application material, account credentials and conversation transcripts.

Engineering decisions are in ADRs 001–003. Changes cover both apps, shared contracts, media scripts and validation infrastructure. The process used generated code as a candidate implementation, then executed the affected behavior.

Findings and corrections:

1. PostgreSQL numeric values were serialized as strings by the driver. Public progress validation failed after a successful write. The adapter now converts and validates numeric fields; API tests cover subsequent reads and concurrent writes.
2. Native SHA-256 verification rejected an ArrayBuffer despite accepting its static type. The download verifier now passes a Uint8Array. This requires a native execution check, not only TypeScript.
3. React Strict Mode detaches refs during development verification. Immediate video cleanup removed the player. Deferred cleanup now distinguishes an actual unmount from a synchronous reattachment; the browser video test exercises playback and return navigation.
4. Retry state was being reset by each playback checkpoint. The outbox now preserves retry timing and its immutable operation across newer local changes, with a lost-response test.
5. The original catalog implementation loaded a capped batch then sliced in memory. It was replaced with counted database pagination and bounded windows.
6. Tool-generated shell setup was unnecessary. Its shell-profile edit was reverted; documentation uses `pnpm run setup` to distinguish the project script from pnpm’s built-in command.

7. Android exposed a download race: the Expo file move returns a promise, but the implementation marked the download ready before the move completed. It now awaits the move and validates the destination before persisting readiness. Typed no-floating-promises lint was added to service and contract code; native replay is required to close the finding.
8. Development API media URLs serialized the request origin as 0.0.0.0 for Android requests. The server now uses its configured public origin; mobile maps local development hosts to its configured API endpoint.
9. GSD-Codex was reviewed at commit 6b306f49d20f5bb245db2ad51e7c7a9491ad028f. Compact state and outcome-based verification were adopted in the existing docs. The installer and agent/model configuration were not run. No-response-as-pass semantics were rejected; test results require evidence.
10. The API client's caller-supplied AbortSignal bypassed its timeout. Both cancellation paths now reach the request, explicit cancellation retains AbortError, and listeners are removed. Three regression tests passed.
11. Largest Dynamic Type testing exposed an oversized brand wordmark and unreliable keyboard navigation through the sign-in form. The wordmark remains fixed with an accessible label; content keeps system scaling. Inputs grow with text, Next focuses Password, and Go submits. A Maestro negative-login flow passed at the largest accessibility size; the simulator font setting was restored.
12. The dependency review updated DOMPurify, esbuild and UUID, and backported a linear URI decoder while retaining the dependency's CommonJS interface. Nineteen domain/SQLite/player tests, API and browser tests, the web build and a disposable migration rollback/reapply passed. The version-based URI advisory remains visible and is documented rather than suppressed.
13. Player review found missed initial readiness, duplicate Play during loading and stale asynchronous seek completions. The player now reads the initial native status, skips an unnecessary zero seek, and invalidates pending work after timeout or replacement. Four behavior tests and the iOS Simulator media navigation flow passed. Physical iPhone playback still stopped at 0:00 for remote and downloaded media after these fixes, so its cause is under separate investigation. Temporary native diagnostics are kept out of committed dependencies and distribution artifacts.
14. Refreshing CocoaPods and compiling Expo Audio from the pinned source restored observed physical iPhone playback in an instrumented build and then a clean build. This is a mitigation with diagnostic limits, recorded in ADR 004. The owner confirmed hearing narration and seeing lock-screen controls; extended acceptance remains separate.
15. A new studio-publishing browser test exposed first-interaction playback rejection for a guest. Web playback was requested only inside the later loadedmetadata callback. It is now requested directly in the user's click, while metadata readiness restores the position. Four browser tests passed, including actual progress advancement after an editor publishes a draft. An initial test selector incorrectly targeted an audio DOM node although the audio engine is detached; the final assertion reads the visible playback position.

16. Session-expiry review found that synchronization displayed a reauthentication message while both profile screens still showed only the signed-in account. A typed authentication-required state now exposes the login form, pauses repeated unauthorized synchronization and retains the account's pending operation. The regression test verifies replay after reauthentication; a browser test removes the session cookie and completes login again without sign-out. Twenty domain tests and five browser tests passed, with formatting, lint and type checks.

17. Remote CI exposed lost keyboard increments in the web seek slider. The controlled input now updates immediately instead of waiting for the media timeupdate event. A separate local playback failure was traced to the OS invoking the MediaSession pause handler; three instrumented runs reproduced it, and three runs with Chromium hardware-media-key handling disabled continued playing. Only the macOS headless test configuration isolates those commands; production external controls remain enabled.
18. Native sign-in reached the API successfully but failed in SecureStore. The simulator had been built with code signing disabled and lacked the application identifier entitlement used for Keychain access. The corrective action is a normally signed simulator build, not a plaintext token fallback. Temporary diagnostics contained only stage names and the Keychain exception and were removed from source after identifying the issue.

19. The requested motion polish applies the pinned official Expo animation skill: short UI-thread transitions, no per-frame React updates, immediate tab switching and reduced-motion handling. A browser rerun exposed a clickable sync action during initial synchronization; it now exposes its disabled state, and the session-expiry test waits for the initial sync to finish before invalidating the cookie. The subsequent five browser tests passed.
20. The native-to-web acceptance runner uses a normally signed simulator app and the second synthetic seed account. It dismisses the system password-save prompt, exercises playback and synchronization, then compares the real SQLite checkpoint with a fresh browser. The final run passed at 64.6597 seconds native and 65 seconds web.
